# Sub2API 托盘工具（sub2api_tray）

在 **Windows 通知区域 / macOS 菜单栏** 里常驻一个小图标，点开就能看到已登录账户的状态，
不必打开浏览器登录 Sub2API 的 Web 管理后台。

![面板预览](docs/panel-preview.png)

## 已具备的能力

* 托盘图标 + 右键菜单（显示面板 / 版本信息 / 退出）；
* 左键单击托盘切换面板，右键弹出菜单；
* 无边框、半透明圆角、置顶、不在任务栏显示的面板窗口；
* 面板自动吸附到托盘图标旁（Windows 在图标上方，macOS 在图标下方），
  并会自动避开屏幕边缘；
* 点击面板外部或按 `Esc` 自动收起；
* 界面中文正常渲染（运行时加载系统中文字体，不额外分发字体文件）；
* 数据文件：`app.json`（环境参数）与 `accounts.json`（账号，预留 API Key）与程序同目录，
  首次运行自动生成，损坏时自动备份重建；
* 密码与 token 经系统密钥库加密后落盘（Windows DPAPI / macOS 钥匙串）；
* 账号名可按 `app.json` 的 `maskAccounts` 开关打码展示；
* 数据目录不可写时，面板顶部显示红色提示，不写任何文件、不静默换目录；
* 面板顶部「登陆新用户」按钮：填实例地址 / 邮箱 / 密码即可登录，支持两步验证（TOTP），
  登录失败按"连不上地址 / 账号或密码有误 / 请求过于频繁"分类提示；
* 登录成功后账号连同加密凭据写入 `accounts.json`，重启后依然存在；
* 托盘右键菜单里每个账号一个**子菜单**：标题显示 `打码邮箱 · 状态`，
  子菜单内「退出账号并删除记录」（删除前会弹确认框）；
* 后台按 `refreshIntervalSeconds`（默认 300 秒）自动刷新：登录态、余额、订阅摘要；
  打开面板时若数据超过 60 秒会立即补刷一次；
* token 过期会自动恢复：先续期，失败再用保存的密码重新登录，仍失败才标记「凭据损坏」；
* 面板里每个账号一张卡片：状态点、角色、地址、余额、订阅摘要、最近刷新时间；
* 托盘悬停提示显示 `N 个账号（M 在线）`；
* **托盘图标右下角的状态圆点**：绿=全部在线、黄=有账号离线、红=有账号凭据损坏、
  无圆点=没有账号或状态还在刷新；
* 手动刷新：托盘右键「立即刷新」或面板总览卡片右侧「立即刷新」，不用等定时周期；
* 账号子菜单「查看 API Key…」：弹窗列出该账号的 Key（名称、打码值、状态、分组、最近使用），
  每行可「复制」完整 Key（只进剪贴板，不落盘）；摘要缓存进 `accounts.json` 的 `apiKeys`；
* 账号卡片收起时**只显示账户名与实例网址**（余额、订阅、刷新时间等都收进展开态）；
* **面板里点账号标题行可展开该账号的 Key 明细**（再点收起）：每个 Key 显示
  已用/总额度、近 5 小时用量、所属订阅名；面板整体可滚动；
* 同时最多登录 **10 个账号**（达到上限后登录会提示先删除一个）；
* 面板底部不再显示数据目录、退出按钮与快捷键提示（退出只在托盘右键菜单里）；
  数据目录不可写时仍用红色横幅提示；
* 鼠标悬浮账号卡片与 Key 行时有约 0.1 秒的平滑高亮（底色与文字同步变化），便于识别可点区域；
* 已登录 10 个账号时顶部「登陆新用户」会置灰并给出说明；
* 右上角齿轮打开**设置页**：账号名打码、状态刷新间隔、请求超时，保存后立即写入 `app.json` 并生效；
* **单实例保护**：重复启动会直接退出并提示已有实例在运行（避免两个副本互相覆盖 `accounts.json`）；
* 断网时展开账号会回退展示**上次缓存的 Key 列表**并标注"可能已过期"；
* **点击 Key 方块即可复制完整 Key**，方块上方会浮出"已复制"提示；
* 设置页可开启**开机自动启动**（登录时静默启动，不弹面板）；
* 设置页可**检查更新**：对比 GitHub Release 版本，发现新版本时显示版本号并可复制下载链接
  （只提示，不自动替换程序）。

## 托盘菜单与状态

右键托盘图标：

```
显示面板
立即刷新
登陆新用户…
─────────────
zh***@ex***.com · 在线  ▸  退出账号并删除记录
li***@ex***.com · 离线  ▸  退出账号并删除记录
─────────────
版本 v0.1.0
─────────────
退出
```

* 账号顺序 = 添加顺序（从早到晚），由 `createdAt` 决定；
* 状态取值：`在线` / `离线` / `刷新中` / `凭据损坏` / `未知`；
* 「凭据损坏」表示 token 续期与密码重登都失败，需要手动重新登录该账号；
* 删除会同时移除 `accounts.json` 里的记录与（macOS 上的）钥匙串条目。

## 登录

1. 点托盘图标打开面板，点最上方的 **＋ 登陆新用户**；
2. 填写三项：
   * **链接**：Sub2API 实例地址，例如 `https://sub2api.example.com`（可带子路径，
     自动去掉尾部斜杠；只支持 http/https）；
   * **账户名**：登录邮箱（后端要求邮箱格式，不是用户名）；
   * **密码**：登录密码（输入框为密文回显）。
3. 点 **确认**（或直接回车）。如果该账号开启了两步验证，弹窗会多出"两步验证码"输入框，
   填 6 位数字后点 **验证并登录**；
4. 成功后面板底部出现"已登录 …"，账号记录写入 `accounts.json`。

失败提示的含义：

| 提示 | 含义 |
| --- | --- |
| 无法连接到该地址，请检查链接与网络 | DNS/连接被拒/超时/HTTPS 证书校验失败 |
| 账号或密码可能有误 | 后端返回 401/403 |
| 请求过于频繁，请稍后再试 | 触发实例登录限流（429） |
| 该地址不是有效的 Sub2API 实例 | 404 或响应不是 Sub2API 的 JSON 信封 |
| 该实例要求人机验证… | 实例开启了 Turnstile/腾讯验证码，需先在 Web 端登录或关闭验证 |
| 验证码不正确或已过期 | 两步验证码错误，或 2FA 会话已过期（重新登录即可） |

注意事项：

* 实例使用 **自签名 HTTPS 证书**时登录会失败（按"无法连接"提示）——请换用受信任证书，
  或先用 http 内网地址；
* 程序遵循系统代理设置；若实例在内网，请确保 `NO_PROXY` 覆盖该地址；
* 密码与 token 只在内存中短暂出现，落盘前用系统密钥库加密；日志里不会出现明文。

## 数据文件

两个文件都放在**可执行文件所在目录**（便携式：程序拷到哪，数据就在哪）。

`app.json`（首次运行自动生成）：

```json
{
  "schemaVersion": 1,
  "maskAccounts": false,
  "refreshIntervalSeconds": 300,
  "requestTimeoutSeconds": 10
}
```

`accounts.json`（登录成功后由程序写入，当前为空）：

```json
{
  "schemaVersion": 1,
  "accounts": []
}
```

说明：

* `maskAccounts` 改成 `true` 后重启，账号名会显示为 `zh***@ex***.com` 这类形式；
* 两个文件改完都需要**重启**才生效（不做热加载）；
* 文件写坏（JSON 语法错误）时，程序会把原文件改名为 `<原名>.corrupt-<时间戳>`，
  再用默认值重建，账号列表不会因此让程序无法启动；
* 账号顺序按 `createdAt`（添加时间）升序，由程序维护。

## 构建与运行

前置条件：

* Rust 1.95 及以上（edition 2024）；
* Windows：MSVC 工具链（Visual Studio Build Tools 的“使用 C++ 的桌面开发”）；
* macOS：Xcode Command Line Tools。

```bash
cargo run                 # 调试运行：启动后只有托盘图标，面板默认隐藏
cargo build --release     # 发布构建
```

调试开关：

```powershell
# Windows：启动即显示面板（便于截图/验收）
$env:SUB2API_TRAY_DEBUG_VISIBLE = "1"; cargo run
# 启动即显示面板并打开登录弹窗（验收弹窗布局）
$env:SUB2API_TRAY_DEBUG_LOGIN = "1"; cargo run
# 打开调试日志
$env:RUST_LOG = "debug"; cargo run
```

```bash
# macOS
SUB2API_TRAY_DEBUG_VISIBLE=1 cargo run
SUB2API_TRAY_DEBUG_LOGIN=1 cargo run
RUST_LOG=debug cargo run
```

## 开发约定（摘要）

完整约定见 [AGENTS.md](AGENTS.md)，几个关键点：

* 所有代码注释使用简体中文，并写清“为什么”；
* `main` 只由维护者合入，功能在独立分支完成后合入 `dev`；
* 每个功能先写 `docs/plans/NNNN-xxx.md`（完成点 + 验收标准）再写代码；
* 提交信息遵循约定式提交（Conventional Commits），描述使用中文。

## 已知限制

* Linux 不在支持范围内；
* macOS 尚未在实机上验收（含钥匙串读写与菜单栏定位）；
* Windows 11 默认会把新托盘图标放进“溢出区”，需要在系统设置里手动固定到任务栏；
* 托盘图标目前是占位图，正式图标待定；
* 程序放在 `Program Files` 等只读目录时无法保存账号，会显示红色提示并要求换目录；
* 暂不支持单实例互斥：同时启动两个副本会互相覆盖 `accounts.json`；
* 自签名 HTTPS 证书的实例无法登录/刷新（会显示"无法连接"）；
* 刷新按账号串行执行，账号很多时一轮会变慢（每个账号 2 个请求 + 200ms 间隔）；

## 发布版本

发布由 GitHub Actions 完成，仓库里只有一条流水线：
`.github/workflows/release-windows.yml`。

1. 功能在 `dev` 上完成并通过验收；
2. 由维护者把 `dev` 合入 `main`；
3. 在 `main` 的最新提交上打 tag 并推送：

   ```bash
   git tag v0.2.0
   git push origin v0.2.0
   ```

4. 流水线会依次执行：
   * **校验 tag 是否在 `main` 历史里**（不在就拒绝发布，避免从功能分支发版）；
   * 质量门禁：`cargo fmt --check`、`cargo clippy --all-targets -- -D warnings`、`cargo test`；
   * 编译 `x86_64-pc-windows-msvc` 的 release 版本；
   * 把 `sub2api_tray-v<版本>-windows-x64.exe` 和同名 `.zip`（便携包）挂到该 tag 的 Release，
     并生成中文发布说明。

**平台范围**：只构建 Windows x64，要求 **Windows 10 及以上**；macOS 暂不构建；
Linux 不在支持范围内。

> 流水线文件必须已经在 `main` 上，tag 触发的构建才会用到它。
