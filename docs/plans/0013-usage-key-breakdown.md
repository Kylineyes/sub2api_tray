## 一、背景

当前用量曲线只能查看账号下全部 Key 的汇总，且用量区跟随账号展开，无法单独收起。
用户还需要按 API Key 查看自己的历史用量，并看到输入、输出、Cache 读写和命中率等指标。
后端用户态 `/usage/dashboard/trend` 已支持可选的 `api_key_id` 过滤，并会校验 Key 归属，
因此非管理员账号也能查询自己的数据，不需要新增后端接口。

## 二、目标

展开账号后，用户可以用「全部 Key」下拉选择汇总或单个 Key，独立展开/收起用量区，
切换总 Token、输入、输出、命中率曲线，并查看完整用量指标。

## 三、范围

包含：

* 用量区标题行独立展开/收起；
* 「全部 Key」下拉选择，选择单个 Key 时请求带 `api_key_id`；
* 按账号、区间、Key 维度缓存，TTL 60 秒；
* 曲线指标切换：总 Token、输入、输出、Cache 命中率；
* 汇总指标：输入、输出、Cache 写入、Cache 读取、命中率、请求数、实际花费；
* 悬浮提示展示该时间桶的完整指标；
* 外部用户角色不参与判断，统一走当前登录账号自己的用户态接口；
* 纯逻辑单测与文档。

不包含：

* 不新增后端接口或修改数据库；
* 不在一张图里同时叠多条 Key 曲线；
* 不做按模型拆分；
* 不引入图表库。

## 五、验收标准

1. 展开账号 -> 用量区出现「全部 Key」下拉和 24 小时/7 天/30 天区间。
2. 选择单个 Key -> 曲线重新加载，只显示该 Key 的数据；切回全部 Key 恢复汇总。
3. 点用量区标题左侧折叠图标 -> 只收起用量区，账号状态和 Key 列表仍可见。
4. 切换总 Token/输入/输出/命中率 -> 曲线和纵轴量纲同步变化。
5. 输入、输出、Cache 写读、命中率、请求、实际花费显示正确。
6. 普通 user 角色账号也可正常加载自己的用量曲线。
7. 断网或单个 Key 无数据 -> 有明确占位/错误文案，不影响 Key 列表复制。

## 七、风险与回滚

| 风险 | 影响 | 应对 |
| --- | --- | --- |
| 每个 Key 单独请求增加调用量 | 触发限流 | 只请求当前选中 Key，按 60 秒缓存，单通道串行 |
| Key 下拉出现时 Key 列表尚未加载 | 只能先看全部 | 保留全部 Key，列表加载后自动出现选项 |
| 命中率分母口径误解 | 指标错误 | 与网页端一致：cache_read / (input + cache_creation + cache_read) |
| 折叠状态丢失 | 重启后恢复展开 | 本次只做会话内折叠，不新增账号文件字段 |

回滚方式：git revert 合并提交。
