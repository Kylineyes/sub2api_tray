# 0022 用量汇总指标改固定宽度流式布局

| 字段 | 内容 |
| --- | --- |
| 编号 | 0022 |
| 分支 | `feat/api-key-quota-adjust` |
| 状态 | 已完成 |
| 提出日期 | 2026-10-21 |

## 一、背景

用量区底部的汇总指标原来最多固定两列：窗口拉宽后每个指标卡片被拉得很长，窗口变窄时又容易
出现某张卡片被压扁或最后一行只剩很小的剩余宽度，视觉不一致。

## 二、目标

让每个汇总指标保持固定宽度，按当前窗口宽度尽可能多地放进同一行，只有放不下时才换行。

## 三、范围

**包含：**

* 汇总指标卡片统一固定宽度与间距；
* 根据可用宽度计算一行最多能放几个；
* 放不下时按行换行，最后一行左对齐；
* 标签被截断时悬浮显示完整文本。

**不包含：**

* 不修改图表、指标选择按钮、区间选择或 API 数据；
* 不新增依赖。

## 四、完成点

* [x] 新增固定宽度常量与每行数量计算函数；
* [x] 用量汇总改为按行分批渲染固定宽度卡片；
* [x] 增加不同宽度下的列数测试；
* [x] 窄窗口与宽窗口实机截图验证。

## 五、验收标准

1. 操作：将托盘缩到常用窄宽度 → 预期：指标卡片保持相同宽度，一行放不下时自动换行。
2. 操作：将托盘横向拉宽 → 预期：同一行容纳更多指标，卡片不会被拉伸变形。
3. 操作：悬浮在较长的指标卡片上 → 预期：可看到完整标签与数值。

## 六、测试方式

**自动化：**

* `cargo fmt --check`
* `cargo clippy --all-targets -- -D warnings`
* `cargo test`（新增 `用量指标按定宽尽可能排满一行`）
* `cargo build --release`

**手工验证：**

* Windows：540×690 物理像素窗口下每行 3 个指标；
  900×800 物理像素窗口下第一行 5 个指标、第二行 3 个指标。

## 七、风险与回滚

| 风险 | 影响 | 应对 |
| --- | --- | --- |
| 固定宽度在极窄窗口放不下 | 卡片截断 | 至少保留一列，并在悬浮时展示完整文本 |
| 宽度常量不适合所有字体缩放 | 标签显示不全 | 使用 hover 文本兜底，后续可再调节常量 |

回滚方式：回退本功能对应提交。
