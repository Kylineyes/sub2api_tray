## 一、背景

`sub2api_tray` 目录里只有一个空的 `README.md`、`LICENSE` 和 Cargo 生成的 `.gitignore`，
还没有任何 Rust 代码，也没有把开发约定固化下来。

工程要长期演进（后续要接 Sub2API 实例、拉取账户状态、做设置页），因此第一步必须先把
三件事定下来，否则后面每个功能都要重新讨论一遍：

1. 这个工程到底做什么（定位与范围）；
2. 代码写成什么样（注释、命名、错误处理、日志的硬性约定）；
3. 怎么协作（分支模型、约定式提交、功能计划与验收标准）。

同时需要一个**能跑起来的最小骨架**：托盘图标存在、面板能弹出能收起，作为后续功能的载体。

## 二、目标

新成员（或 AI 代理）读完 `AGENTS.md` 就能按约定提交代码，并且 `cargo run` 后能看到
托盘图标与一个可弹出/收起的面板。

## 三、范围

**包含：**

* `AGENTS.md`：工程定位、技术栈、目录与模块边界、中文详注规范、代码规范、
  分支模型与提交流程、功能计划模板与验收标准、平台差异备忘、安全约定；
* 功能计划模板 `docs/plans/TEMPLATE.md` 与本文档；
* Rust 工程骨架：`cargo` 包、依赖、入口、托盘模块、面板模块、字体模块；
* 系统托盘图标与右键菜单（显示面板 / 版本 / 退出）；
* 无边框、置顶、不在任务栏显示的面板窗口，可按托盘图标位置定位；
* 面板的显示/隐藏状态机：左键托盘切换、点击外部收起、Esc 收起、退出；
* 运行时加载系统中文字体（egui 默认字体不含中文，否则界面全是方块）；
* 定位计算的单元测试；
* README 使用说明。

**不包含（明确排除）：**

* 与 Sub2API 实例的任何通信（登录、账户列表、用量）；
* 设置页、开机自启、单实例、自动更新；
* 自定义设计的正式托盘图标（当前用脚本生成的占位图）；
* macOS 的 Dock 图标隐藏（`ActivationPolicy::Accessory`）与实机验收；
* Linux 支持。

## 五、验收标准

1. 操作：`cargo fmt --check` → 预期：退出码 0，无格式差异。
2. 操作：`cargo clippy --all-targets -- -D warnings` → 预期：退出码 0，零警告。
3. 操作：`cargo test` → 预期：5 个定位相关测试全部通过。
4. 操作：`cargo build` → 预期：产出 `target/debug/sub2api_tray.exe`（macOS 为无后缀二进制）。
5. 操作：`SUB2API_TRAY_DEBUG_VISIBLE=1 cargo run` → 预期：托盘区域出现图标；
   面板出现在托盘图标旁边（Windows 在图标上方、右边缘对齐），四角为圆角且透明；
   界面中文正常显示，不出现方块。
6. 操作：面板显示时点击另一个窗口 → 预期：面板自动收起（窗口不可见）。
7. 操作：面板隐藏后点击托盘图标 → 预期：面板重新出现（验证隐藏状态下逻辑仍在运行）。
8. 操作：点击托盘图标弹出面板后再次点击图标 → 预期：面板收起且不会立刻弹回
   （去抖生效）。
9. 操作：右键托盘图标 → 预期：菜单包含“显示面板 / 版本 v0.1.0 / 退出”；
   点击“退出”进程结束。
10. 操作：面板显示时按 `Esc` → 预期：面板收起。

## 七、风险与回滚

| 风险 | 影响 | 应对 |
| --- | --- | --- |
| Windows 上 wgpu 不支持透明交换链，圆角变成方块 | 观感明显变差 | 固定 `Renderer::Glow`（已采用） |
| 托盘图标在 Windows 11 默认进入“溢出区”，用户看不到 | 无法操作 | 系统设置里可固定到任务栏；后续版本考虑首次启动提示 |
| 面板失焦判定在个别环境拿不到 `focused` | 面板不自动收起（不会影响可用性） | 拿不到时按“仍然聚焦”处理 |
| 点击托盘关闭面板时被再次触发显示 | 面板闪一下又回来 | 250ms 去抖 + 400ms 聚焦宽限期（已实现） |
| macOS 分支代码未经实机验证 | 可能在 mac 上布局/定位异常 | 已在文档中标注，后续单独开 macOS 验收计划 |
| 系统中文字体缺失 | 界面显示方块 | 多候选字体 + 警告日志，不阻断启动 |

回滚方式：本功能为纯新增，`git revert` 合并提交即可回到只有 README 的状态。
