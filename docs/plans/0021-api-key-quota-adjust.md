| 字段 | 内容 |

## 一、背景

托盘当前已经能按账号展开 API Key 列表，但列表只读：用户看到某个 Key 额度不合适或需要停用某个 Key 时，
仍必须打开浏览器进入 Sub2API Web 后台逐项操作。Sub2API 的用户态接口
`PUT /api/v1/keys/{id}` 与 `DELETE /api/v1/keys/{id}` 已分别支持额度调整和删除，
托盘具备补齐这两项能力的条件。

另外，Key 列表里的近 5 小时数据来自额度接口的 `usage_5h` 字段。服务端只有在 Key
配置了 5 小时限速窗口时才累计该字段；未配置限速时它恒为 0。界面必须把这种情况明确标成
未启用限速统计，不能让人误以为近期真实用量为 0。

## 二、目标

在账号展开后的每个 API Key 上提供调额度与删除入口，用户无需打开浏览器即可管理自己的单个 Key，
并准确理解近 5 小时用量字段的统计条件。

## 三、范围

**包含：**

* 展开账号后的每个 Key 行增加调额度与删除按钮；
* 调额度弹窗展示 Key、当前已用额度与当前额度，支持 `0` 表示不限额、同时清零已用额度；
* 新额度低于已用额度时提示会立即耗尽；
* 删除 Key 前二次确认，明确提示删除不可恢复；
* 后台线程调用 `PUT /api/v1/keys/{id}` 与 `DELETE /api/v1/keys/{id}`；
* 成功后更新面板缓存与 `accounts.json`；删除后清理对应用量筛选缓存；
* 未启用 5 小时限速时显示未启用限速统计，而不是展示容易误解的 0；
* 失败时保留弹窗和用户输入，展示可读错误。

**不包含（明确排除）：**

* 不修改 Key 名称、分组、状态、过期时间或限速窗口；
* 不增加创建 Key 或管理其他用户 Key 的能力；
* 不改 Sub2API 后端；
* 不新增第三方依赖。

## 五、验收标准

1. 操作：展开账号并悬浮某个 Key → 预期：只在该 Key 下方显示复制、调额度、删除三个按钮；
   鼠标移开后按钮隐藏。点击 Key 标题不会复制。
2. 操作：点击某个 Key 的调额度 → 预期：弹窗打开，显示该 Key、已用额度和当前额度。
3. 操作：输入 `20.5` 并保存 → 预期：请求成功后弹窗关闭，该 Key 显示新额度，缓存同步更新。
4. 操作：额度已耗尽的 Key 输入 `0` 并勾选清零 → 预期：成功后显示不限额、已用额度为 0。
5. 操作：输入 `-1` 或非数字 → 预期：不发送请求，弹窗内显示输入错误。
6. 操作：新额度低于已用额度且未勾选清零 → 预期：弹窗提示会立即达到上限。
7. 操作：点击删除 → 预期：出现二次确认，展示 Key 名称与打码值；取消不会发请求。
8. 操作：确认删除 → 预期：请求成功后 Key 从列表与缓存中消失，若正在按该 Key 筛选用量则自动回到全部 Key。
9. 操作：Key 未配置 5 小时限速 → 预期：显示未启用 5 小时限速统计，而不是近 5 小时 $0.00。
10. 操作：请求失败 → 预期：弹窗不关闭，保留操作状态并显示错误原因。

## 七、风险与回滚

| 风险 | 影响 | 应对 |
| --- | --- | --- |
| 旧版 Sub2API 不支持额度更新或删除 | 操作失败 | 展示服务端错误，不修改本地缓存 |
| 误删正在使用的 Key | 客户端立即失效 | 二次确认并明确展示 Key 名称与打码值 |
| 额度低于已用值时立即触发限制 | 用户误操作 | 保存前展示警告并提供清零选项 |
| 请求期间重复点击 | 重复提交 | 同一时间只允许一个在途请求，按钮禁用 |
| 把未启用限速误读为真实 0 用量 | 用户误判 | 使用限速配置字段判断并显示明确文案 |

回滚方式：回退本功能对应提交；不影响已有 Key 查看与复制功能。
