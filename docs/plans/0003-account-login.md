## 一、背景

0002 提供数据层后，工程仍然没有任何"添加账号"的入口。需求方要求：

* 面板**最顶部**显示「登陆新用户」按钮；
* 点击后出现弹窗，填写**链接 / 账户名 / 密码**，确认后尝试登录；
* 成功即关闭弹窗；失败提示"链接、账户、密码可能错误"。

已与需求方确认：登录失败按**三类**提示（连不上地址 / 凭据错误 / 频率限制），
并要求支持**手输 TOTP**。

## 二、目标

用户能在面板顶部点开登录弹窗，填写三个字段完成一次真实登录；成功后账号立即出现在
`accounts.json` 与托盘菜单（0004）；失败时得到准确、可行动的中文提示。

## 三、范围

**包含：**

* 面板顶部「登陆新用户」按钮（替换当前禁用的「登录账户」占位按钮）；
* egui 模态弹窗：链接（URL）、账户名（邮箱）、密码（密文回显），确认/取消；
* 输入校验：URL 必须 http/https 且能归一化；账户名必须是邮箱格式（后端 `binding:"required,email"`，
  非邮箱会被直接 400）；密码非空；
* 真实登录：`POST {base}/api/v1/auth/login`，解析 `{code,message,data}` 信封；
* 2FA：响应 `data.requires_2fa == true` 时，把 `data.temp_token` 暂存，弹窗切换出 6 位验证码输入，
  提交 `POST {base}/api/v1/auth/login/2fa {temp_token, totp_code}`；
* 登录成功：用 `access_token` 调 `GET /api/v1/auth/me` 取 `role` 与用户信息 → 组装账号 →
  `accounts.add`（唯一性校验）→ 加密保存密码与 token → 关闭弹窗；
* 失败分类映射（见 4.3）与弹窗内错误提示；
* HTTP 在后台线程执行，界面不卡死；提交中禁用按钮并显示"登录中…"；
* 单元测试：URL 归一化、邮箱校验、信封解析、错误分类、2FA 状态机。

**不包含（明确排除）：**

* Turnstile / 腾讯验证码：若实例强制人机验证，按 4.3 的专用文案提示去 Web 端登录；
* 账号列表、托盘菜单、状态刷新 → 0004；
* 修改密码、找回密码、注册；
* 多实例负载均衡或自动重试（登录失败只提示，不自动重试）；
* 记住"上次登录的地址"（后续可加，需要时单独立计划）。

## 四、设计要点（需评审）

### 4.1 登录交互状态机

```
Idle ──点「登陆新用户」──▶ Editing ──点「确认」──▶ Submitting
                              ▲                      │
                              │            ┌─────────┼──────────┐
                              │            ▼         ▼          ▼
                              │        NeedTotp   Succeeded   Failed(类)
                              │            │         │          │
                              └────────────┴─────────┘          └─▶ 保留输入，显示错误
```

* `NeedTotp` 额外显示 6 位数字输入框与"验证码"说明，可返回上一步；
* `Submitting` 期间禁用所有输入与按钮，只保留"取消"；
* 成功后清空密码字段（内存里的副本）并关闭弹窗。

### 4.2 与后端的契约（已核对后端源码）

| 项 | 内容 |
| --- | --- |
| 登录 | `POST {base}/api/v1/auth/login`，JSON `{email, password}` |
| 成功响应 | HTTP 200 + `{"code":0,"message":"success","data":{access_token, refresh_token, expires_in, token_type, user}}` |
| 需要 2FA | HTTP 200 + `{"code":0,"data":{"requires_2fa":true,"temp_token":"…","user_email_masked":"z***@e***.com"}}` |
| 2FA 完成 | `POST {base}/api/v1/auth/login/2fa`，JSON `{temp_token, totp_code}`（6 位） |
| 当前用户 | `GET {base}/api/v1/auth/me`，Header `Authorization: Bearer <access_token>` |
| 错误响应 | HTTP 4xx/5xx + `{code, message, reason}`；`code` 与 HTTP 状态一致 |

`temp_token` 随 2FA 会话有过期时间，过期后重试会失败 → 提示"验证码会话已过期，请重新登录"。

### 4.3 错误分类（写死映射，单元测试覆盖）

| 触发条件 | 提示文案 |
| --- | --- |
| DNS 解析失败 / 连接被拒 / 连接超时 / TLS 证书错误 | 「无法连接到该地址，请检查链接与网络」 |
| HTTP 401 / 403 | 「账号或密码可能有误」 |
| HTTP 429 | 「请求过于频繁，请稍后再试」 |
| HTTP 404 或响应不是 Sub2API 信封（无 `code` 字段） | 「该地址不是有效的 Sub2API 实例」 |
| 服务端明确返回人机验证相关错误 | 「该实例要求人机验证，请先在 Web 端登录或关闭验证」 |
| 2FA 验证码错误 | 「验证码不正确或已过期」 |
| 其他 4xx / 5xx | 「实例返回异常（HTTP xxx）」 |

所有文案都保持在弹窗内，不弹系统通知，不写入日志中的凭据信息。

### 4.4 HTTP 与线程

* 依赖 `ureq`（rustls，无 OpenSSL），超时取 `app.json` 的 `requestTimeoutSeconds`；
* 每次提交 spawn 一个工作线程，通过 `std::sync::mpsc` 把 `LoginOutcome` 回传；
* 收到结果后 `ctx.request_repaint()`，在 `App::logic` 中消费结果并更新状态机；
* 禁止在主线程做任何阻塞 IO。

### 4.5 成功后落库

```text
归一化 baseUrl（去尾部斜杠、小写 scheme/host）
→ 校验 baseUrl + email 唯一（0002 的 accounts.add）
→ 组装 Account { role 来自 /auth/me, createdAt = 现在 }
→ SecretStore::seal({ password, access_token, refresh_token }) 得到 secrets
→ accounts.save()（原子写）
```

落库失败（如磁盘满、目录不可写）→ 弹窗保持打开并提示「保存账号失败：<原因>」，
此时不关闭弹窗，避免"表面成功但没记住"。

## 六、验收标准

1. 操作：面板打开后看顶部 → 预期：显示「登陆新用户」按钮，位置在标题与状态卡片之间，
   点击后出现带三个输入框的模态弹窗（弹窗遮罩面板内容，`Esc`/取消可关闭）。
2. 操作：链接填 `http://127.0.0.1:8080/`（尾部斜杠）+ 一个真实存在的邮箱与正确密码 → 预期：
   按钮变为"登录中…"，成功后弹窗关闭，`accounts.json` 多出 1 条记录，
   其 `baseUrl` 为 `http://127.0.0.1:8080`（去掉尾斜杠），`secrets` 非明文，`role` 与后端一致。
3. 操作：同上但密码填错 → 预期：弹窗不关闭，红字提示「账号或密码可能有误」，输入内容保留。
4. 操作：链接填 `http://127.0.0.1:1`（无服务）→ 预期：提示「无法连接到该地址，请检查链接与网络」，
   且**不会**提示密码错误。
5. 操作：账户名填 `not-an-email` → 预期：点击确认前即提示"请输入有效的邮箱地址"，不发请求。
6. 操作：对一个开启 2FA 的账号登录 → 预期：弹窗切换出 6 位验证码输入；输入正确后登录成功；
   输入错误提示「验证码不正确或已过期」，且可重试。
7. 操作：对同一 URL + 同一邮箱再次登录 → 预期：提示「该账号已存在」，不产生重复记录。
8. 操作：登录成功后重启程序 → 预期：重启后（配合 0004）该账号仍在列表中，无需重新登录。
9. 操作：`cargo test` → 预期：上述纯函数与状态机用例全部通过。

## 八、风险与回滚

| 风险 | 影响 | 应对 |
| --- | --- | --- |
| `ureq` 的 TLS 根证书在旧系统缺失 | 访问 HTTPS 实例失败 | 归类为"无法连接"，文案提示检查网络；必要时改用系统证书库 |
| 2FA 会话过期 | 用户输完验证码仍失败 | 明确提示"请重新登录"，回到 Editing |
| 登录成功后写盘失败 | 用户以为已保存 | 弹窗不关闭并报错（4.5） |
| 输入密码残留在内存 | 内存转储泄露 | 只保留 `egui` 输入缓冲，提交后清空；不在日志中出现 |
| 实例返回 200 但信封异常 | 误判成功 | 必须同时校验 `code == 0` 且 `data.access_token` 非空 |

回滚：本计划新增 `login.rs`/`api.rs` 与面板顶部按钮，`git revert` 合并提交即可；
已写入的账号记录不受影响（0002 数据层独立）。

### 与计划的偏差

1. **按钮位置**：实现为"标题区（面板最顶部）整行按钮"，而不是放在状态卡片下方；
   与原「登录账户」占位按钮一样被移除，避免两个登录入口并存。
2. **新增调试开关 `SUB2API_TRAY_DEBUG_LOGIN`**：自动化无法点击按钮，需要它来截图验收弹窗。
3. **端到端测试从"可选 1 个"变成 2 个**：分别覆盖 HTTP 客户端层与登录线程（含 2FA）层。
4. **登录成功但 `/auth/me` 失败**：角色记为 `Unknown` 并照常保存账号（计划未明确）。
   理由：token 已经拿到，账号可用；角色只影响后续展示分岔，不该让登录整体失败。
5. **取消/提交按钮**：用闭包内局部标志实现，没有走 egui 临时数据（初版写法已废弃）。

### 遗留问题

* 未处理自签名 HTTPS 证书（会按"无法连接"提示）；如需支持，要单独加"忽略证书校验"开关并
  明确风险；
* 未接入 Turnstile/腾讯验证码，只给出提示文案；
* 未在真实实例上做过手工登录（缺少可运行的本地后端环境）；
* macOS 未实机验收（按约定延后）；
* 测试中曾出现一次并行执行偶发失败，原因是假实例按"请求到达顺序"分发响应；
  已改为"按路径分发 + 非阻塞 accept + 停止标志"，随后连续 15 次全绿。
