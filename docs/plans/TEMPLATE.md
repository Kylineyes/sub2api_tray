# 功能计划模板

> 复制本文件为 `NNNN-<英文短名>.md`（编号从 0001 起递增，不跳号、不复用），
> 按下表逐项填写后再动手写代码。字段不适用时写“无”，不要留空。

| 字段 | 内容 |
| --- | --- |
| 编号 | NNNN |
| 分支 | `feat/xxx` / `fix/xxx` / `chore/xxx` / `docs/xxx` |
| 状态 | 计划中 / 进行中 / 已完成 / 已合入 dev |
| 提出日期 | YYYY-MM-DD |

## 一、背景

为什么要做这件事？现在是什么状态？不做会有什么问题？

## 二、目标

用一句话说明“完成后用户能做什么”，避免写成实现细节。

## 三、范围

**包含：**

* 逐条列出本次要交付的能力。

**不包含（明确排除）：**

* 逐条列出容易被顺手带进来、但本次不做的内容，避免范围蔓延。

## 四、完成点

* [ ] 完成点一（可独立验证的最小单元）
* [ ] 完成点二
* [ ] 完成点三

## 五、验收标准

必须可执行、可观测。每条写清“怎么操作 → 观察到什么”。

1. 操作：…… → 预期：……
2. 操作：…… → 预期：……

## 六、测试方式

**自动化：**

* `cargo fmt --check`
* `cargo clippy --all-targets -- -D warnings`
* `cargo test`（列出新增的测试用例）
* `cargo build`

**手工验证（按平台分别记录）：**

* Windows：……
* macOS：……

## 七、风险与回滚

| 风险 | 影响 | 应对 |
| --- | --- | --- |
| …… | …… | …… |

回滚方式：`git revert <合并提交>` 或直接把 `dev` 回退到本功能合入前的提交。

## 八、涉及文件

* `src/xxx.rs`（新增/修改，预计改动点）
* `docs/plans/NNNN-xxx.md`

## 九、结果

> 功能完成后填写，随功能分支一起提交。

* 实际验证记录（命令输出要点、手工操作结果）：
* 与计划的偏差：
* 遗留问题 / 后续计划编号：
