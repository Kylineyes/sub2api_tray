## 一、背景

三件事同时做：两个副本会互相覆盖 `accounts.json`；改打码/刷新间隔只能手改 `app.json`；
断网时 Key 明细直接报错，看不到上次结果。另外 Key 行的悬浮高亮太弱，看不清选区。

## 二、范围

* **单实例锁**：在 `127.0.0.1:45917` 上 `bind`，占用即代表已有实例；第二个实例打印原因后退出。
  用**固定端口**而不是端口段——端口段会让第二个实例"礼貌地"换个端口绑上，锁等于没有
  （第一版实现就踩了这个坑，已由单测覆盖）。
* **设置页**：面板右上角齿轮 → 弹窗改「账号名打码 / 状态刷新间隔 / 请求超时」，
  保存后写 `app.json` 并立即生效（打码会重建菜单与卡片）。
* **离线缓存回退**：Key 拉取失败时读 `accounts.json` 的 `apiKeys` 缓存展示，
  并标注"缓存数据 · 可能已过期"。
* **高亮块加强**：整行深色方块（更亮的底色 + 品牌色描边 + 内外边距），不再靠叠加半透明白。

## 三、验收标准

1. 启动两个副本 → 预期：第二个立即退出，日志与 stderr 提示"已有一个实例在运行"；
   第一个退出后可再次启动。
2. 点齿轮 → 改打码开关 → 保存 → 预期：菜单与卡片立即打码，`app.json` 已更新；重启后仍生效。
3. 改刷新间隔/超时 → 保存 → 预期：下一轮刷新按新间隔；请求超时按新值（日志/行为可观察）。
4. 断网后展开账号 → 预期：显示缓存 Key 并标注"可能已过期"，不再是一片错误。
5. 鼠标移到 Key 行 → 预期：整行出现明显方块高亮（含描边），文字更亮。
6. `cargo test` → 全部通过（含单实例用例）。

## 四、结果

* 单实例已实机验证：A 存活、B 退出，日志 `已有一个 Sub2API 托盘实例在运行（本机端口 45917 已被占用）`；
* `cargo fmt --check` / `clippy -D warnings` / `cargo test`（90 passed）/ `build` 全绿；
* 设置页与缓存回退的交互需人工点击确认（无法自动化）。

## 五、遗留

* 设置页暂不含"开机自启""自动更新"（阶段 3 剩余项）；
* 缓存回退只用于面板展开，弹窗（菜单入口）仍是纯实时拉取。
