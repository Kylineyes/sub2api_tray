## 一、背景

需求方在验收 0006 后提出 5 条改动：

1. 复制功能已通过；
2. **数据目录默认不在面板底部展示**；
3. **同时最多登录 10 个账号**；
4. 账号列表要能**滚动遍历**；
5. 点击某个账号**展开**其全部 API Key（已用额度/总额度、最近用量、所属订阅名），
   **再点一次收起**。

关于"托盘"：本项目里"托盘顶部按钮"等说法一直指**点托盘图标弹出的面板**。
原生右键菜单无法真正滚动、也无法在菜单内展开，因此第 4、5 条落在**面板**里实现。

## 二、目标

面板里账号卡片可点击展开/收起 Key 明细；列表可滚动；账号上限 10；底部不再显示数据目录。

## 三、范围

**包含：**

* 移除面板底部的"数据目录：…"行（数据目录不可写时仍有红色横幅提示）；
* `save_login` 落库前校验账号数，达到 10 个时提示「最多同时登录 10 个账号…」；
* 面板账号卡片标题行可点击：`▸`/`▾` 指示，点击展开后内联显示该账号的 Key 列表；
* 每个 Key 展示：名称 + 打码值、已用额度/总额度、近 5 小时用量、订阅名；
* 展开时按需拉取（带缓存，再次展开不重复请求）；同一时间只允许一个拉取任务；
* 面板内容区保持可滚动（沿用 0004 的 `ScrollArea`）。

**不包含：**

* 在右键菜单里展开（原生菜单限制）；
* Key 的创建/删除（0006 已确认只读）；
* **"最近 1 小时"用量**：实例接口只提供 `usage_5h / usage_1d / usage_7d`，
  没有 1 小时口径，本期展示"近 5 小时"并如实标注；要 1 小时需后端新增字段。

## 四、设计要点

1. **展开状态**：`expanded_accounts: HashSet<String>`；明细缓存在
   `account_keys: HashMap<String, AccountKeysState>`（含 loading/error/keys）。
2. **点击命中**：卡片标题行用 `Response::interact(Sense::click())` 包一层，
   避免把整张卡片变成按钮（卡片内还有文本选择/滚动）。
3. **拉取**：复用 0006 的 `list_api_keys`；结果同时写回 `accounts.json` 的 `apiKeys` 缓存。
4. **额度展示**：`quota_used / quota`；`quota` 为空或 0 时显示"不限"。
5. **订阅名**：优先用 Key 自带的 `group.name`，否则回退到账号订阅摘要里的分组名。

## 六、验收标准

1. 操作：打开面板 → 预期：底部**不再**出现"数据目录：…"；数据目录不可写时仍有红色横幅。
2. 操作：已登录 10 个账号后再登录第 11 个 → 预期：弹窗提示「最多同时登录 10 个账号…」，
   不写入 `accounts.json`。
3. 操作：账号较多时滚动面板 → 预期：可滚动遍历全部账号。
4. 操作：点某个账号标题行 → 预期：箭头变 `▾`，下方出现该账号的 Key 列表
   （名称+打码值、已用/总额度、近 5 小时用量、订阅名）；再点一次收起。
5. 操作：首次展开后再次展开 → 预期：不再重复请求（用缓存），立即显示。
6. 操作：`cargo test` → 预期：全部通过（默认套件不依赖网络）。

## 八、风险与回滚

| 风险 | 影响 | 应对 |
| --- | --- | --- |
| 展开时发请求拖慢面板 | 点击后短暂 loading | 后台线程 + 缓存，同一时间只跑一个 |
| 账号多 + 展开后列表很长 | 面板拥挤 | 面板整体可滚动，单卡片内不再嵌套滚动 |
| 10 个上限把老用户挡住 | 无法新增 | 提示明确，需先删除一个 |

回滚：`git revert` 合并提交；账号上限常量改回即可放开。
