## 一、背景

用量汇总使用 `horizontal_wrapped` 连续摆放 8 个指标标签。面板较窄时，
前面的标签占满宽度，最后一个标签只剩几像素，文字被压成一字一行。

## 二、目标

指标标签按可用宽度自动分列，每列保持可读的最小宽度，不再出现竖排文字。

## 三、范围

包含：

* 根据可用宽度计算 1-4 列；
* 每行手动布局固定宽度标签；
* 标签文字单行显示，超长时截断；
* 单测覆盖列数计算；
* 窄窗口实机截图。

不包含：

* 不改变指标数据；
* 不改变曲线绘制。

## 四、完成点

* [x] 指标区改为响应式网格
* [x] 标签固定最小宽度、单行显示
* [x] 列数计算单测
* [x] 实机与文档

## 五、验收标准

1. 面板窄至 320px -> 指标按 2-3 列排列，无竖排文字。
2. 面板较宽 -> 最多 4 列，标签不无限拉伸。
3. 所有 8 个指标（总/输入/输出/命中率/Cache 写读/请求/花费）都可见。
4. 超长数值时标签截断，不破坏布局。

## 六、测试方式

* cargo fmt --check
* cargo clippy --all-targets -- -D warnings
* cargo test --locked
* cargo build --release --locked
* Windows 实机窄窗口截图

## 七、风险与回滚

| 风险 | 影响 | 应对 |
| --- | --- | --- |
| 列数过多导致标签过窄 | 数值被截断 | 最小列宽约 96 点，最多 4 列 |
| 实际 spacing 与计算不一致 | 最后一列溢出 | 每行显式设置 4px item spacing |

回滚方式：git revert 合并提交。
