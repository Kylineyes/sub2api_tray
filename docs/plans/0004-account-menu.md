## 一、背景

0002 有了持久化，0003 有了登录入口，但账号还"看不见"：托盘右键菜单仍只有
「显示面板 / 版本 / 退出」，面板下半部分仍是"账户状态列表"占位卡片。

需求方要求：

* 每个账号在**托盘内展示**，顺序为**添加时间从早到晚**；
* 每个账号是**一个子菜单**，子菜单里的「退出账号并删除记录」可清除该账号；
* 账号状态在托盘内可见（已确认：状态写进子菜单标题，余额/订阅摘要放面板）；
* 打码开关（0002 的 `maskAccounts`）生效于展示。

## 二、目标

托盘右键菜单按添加顺序列出所有已登录账号及其状态；点「退出账号并删除记录」并确认后，
账号从菜单、面板与 `accounts.json` 中同时消失；面板里能看到每个账号的余额与订阅摘要。

## 三、范围

**包含：**

* 托盘右键菜单结构：登录相关入口 + 账号子菜单 + 版本 + 退出；
* 每个账号一个 `Submenu`，标题 = `打码邮箱 · 状态`；
* 子菜单项：`退出账号并删除记录`（未来 API Key 管理项占位在文档里，不实现）；
* 状态刷新：登录态（`/auth/me`）+ 余额/订阅摘要（`/subscriptions/summary`），
  节奏由 `app.json` 的 `refreshIntervalSeconds` 决定（默认 300 秒），启动后 5 秒首刷；
* token 失效恢复链：401 → 用 `refresh_token` 调 `/api/v1/auth/refresh` → 仍失败则用加密保存的
  密码自动重登 → 再失败标记「凭据损坏」；
* 删除流程：菜单项点击 → 弹出面板并显示确认对话框 → 确认后删除记录 + macOS 清钥匙串条目；
* 面板账号列表：打码邮箱、URL、角色、状态、余额、订阅摘要、最后刷新时间；
* 托盘 tooltip 更新为 `Sub2API 托盘 · N 个账号（M 在线）`；
* 菜单在账号增删、状态变化、打码配置变化（重启后）时重建。

**不包含（明确排除）：**

* API Key 的增删改查（子菜单里只留位置，不实现）；
* 账号编辑（改 URL / 改密码 / 改角色）；
* 手动"立即刷新"按钮（后续按需）；
* 状态变化的系统通知；
* 托盘图标按状态换色/换图（阶段 2 的内容，单独计划）；
* 单实例互斥。

## 四、设计要点（需评审）

### 4.1 菜单结构

```text
Sub2API 托盘
├── 显示面板
├── 登陆新用户…            ← 0003 的入口，此处复用（点开面板并打开弹窗）
├── ─────────────
├── zh***@ex***.com · 在线   ▸   等待子菜单展开…
│                                └── 退出账号并删除记录
├── li***@ex***.com · 离线   ▸
│                                └── 退出账号并删除记录
├── ─────────────
├── 版本 v0.1.0
├── ─────────────
└── 退出
```

* 顺序：`createdAt` 升序（添加从早到晚）；
* 子菜单标题里的邮箱按 `maskAccounts` 打码（0002 的 `mask_email`），超长截断为
  `前 20 字符…`，避免菜单过宽；
* 状态值：`在线` / `离线` / `刷新中` / `凭据损坏`（`unknown` 显示为 `未知`）；
* 账号数量不设硬上限；超过 15 个时菜单会很长，属可接受行为（风险表记录）。

### 4.2 状态刷新

```text
每 refreshIntervalSeconds：
  for 每个账号（串行，间隔 200ms，避免打满实例）：
    GET /api/v1/auth/me            → role、用户信息、余额
    GET /api/v1/subscriptions/summary → items[]（组名、日/周/月已用、限额）
  汇总写入内存状态 → 重建菜单 → request_repaint()
```

* 首刷：启动后 5 秒（等托盘与窗口就绪），登录成功后立即刷新该账号；
* 打开面板时若某账号数据超过 60 秒，触发一次单账号刷新；
* 401/403 依次尝试：`/auth/refresh`（`{refresh_token}`）→ 失败则用存储密码重新登录 →
  再失败标记「凭据损坏」并停止对该账号自动重试（用户需重新登录）；
* `/auth/refresh` 有 30 次/分钟限流，因此同一账号失败后至少静默 60 秒再试；
* 网络失败只影响状态显示（标记「离线」），不修改 `accounts.json`、不删除账号。

### 4.3 删除流程

1. 用户点「退出账号并删除记录」；
2. 若面板未显示 → 先 `show_panel`（因为确认对话框画在面板里，与 0003 同一套 `Modal`）；
3. 面板内弹出确认框：`确定退出 <打码邮箱> 并删除记录？删除后需重新登录才能恢复。`；
4. 确认 → `accounts.remove(id)`（原子写）→ macOS 删除钥匙串条目 → 重建菜单 →
   面板提示"已删除"；取消 → 不做任何变更。

### 4.4 面板账号列表

替换现有"账户状态列表"占位卡片：

```text
┌─────────────────────────────────┐
│ ● zh***@ex***.com        管理员  │
│   http://10.0.0.5:8080          │
│   在线 · 余额 $12.30             │
│   日 1.2/5.0 · 周 4.0/20 · 月 9/60│
│   2 分钟前刷新                   │
└─────────────────────────────────┘
```

* 状态点颜色：在线=品牌绿、离线=灰、刷新中=蓝、凭据损坏=红；
* 列表可滚动（账号多时面板高度固定 460pt）；
* 空列表沿用现有"尚无账号"提示，并引导点击顶部「登陆新用户」。

### 4.5 线程与重建约束

* `tray-icon`/`muda` 的菜单对象**不是** `Send`，只能在主线程创建与设置：
  `TrayHandle` 增加 `set_menu(&self, menu)` 与 `set_tooltip(&self, text)`；
* 刷新在后台线程完成，结果通过既有的 `TrayBridge` 队列回传，主线程统一更新状态并重建菜单；
* 禁止在托盘回调里直接重建菜单（回调线程不一定是 UI 线程）。

## 六、验收标准

1. 操作：登录 3 个账号（间隔添加）后右键托盘 → 预期：菜单出现 3 个账号子菜单，
   顺序与添加顺序一致，标题形如 `zh***@ex***.com · 在线`。
2. 操作：把 `app.json` 的 `maskAccounts` 改为 `true` 后重启 → 预期：菜单与面板中的邮箱均打码；
   改回 `false` 重启后恢复完整邮箱。
3. 操作：等待 `refreshIntervalSeconds` 到期 → 预期：状态从「刷新中」变为「在线」，
   面板里"最后刷新时间"更新；断网后下一轮变为「离线」，账号不被删除。
4. 操作：手动让某个账号的 access_token 失效（重启后端或等服务端过期）→ 预期：
   自动走 refresh/重登，状态仍为「在线」；若密码已改则变为「凭据损坏」。
5. 操作：右键某账号 → 点「退出账号并删除记录」 → 预期：面板弹出并显示确认框，
   文案含打码邮箱；取消后账号仍在。
6. 操作：在确认框点"删除" → 预期：该账号子菜单立即消失，`accounts.json` 中对应记录被移除，
   面板提示"已删除"，重启后不应恢复；Windows 上钥匙串/DPAPI 密文随记录删除。
7. 操作：添加超过 15 个账号 → 预期：菜单仍能正常展开（长度变长但不崩溃），
   面板列表出现滚动条。
8. 操作：`cargo test` → 预期：菜单标题、排序、退避与恢复链决策用例全部通过。

## 八、风险与回滚

| 风险 | 影响 | 应对 |
| --- | --- | --- |
| 账号过多导致托盘菜单过长 | 操作体验差 | 不截断（避免"消失的账号"），文档说明；后续可加分页或"面板优先" |
| 频繁重建菜单 | 菜单闪烁/资源占用 | 仅在账号或状态变化时重建，最多每轮刷新一次 |
| 刷新打满实例或触发 429 | 状态变成离线、误判凭据失效 | 串行 + 200ms 间隔 + 失败退避 60 秒 |
| 自动重登把账号锁死 | 连续失败触发实例风控 | 仅在一次 401 后尝试一次，失败即标记凭据损坏并停止重试 |
| 删除时写盘失败 | 菜单已删但文件仍有记录 | 先写盘成功再更新菜单；失败提示并保持原状 |
| 面板卡片信息过多 | 小窗口拥挤 | 固定 460pt 高度 + 滚动，摘要单行省略 |

回滚：`git revert` 合并提交；已删除的账号无法回滚（确认框已提示），
已登录账号记录保留在 `accounts.json` 中。
