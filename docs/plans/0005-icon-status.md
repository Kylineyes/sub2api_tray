## 一、背景

0004 之后账号状态已经能刷新，但**只有打开面板或右键菜单才看得到**：
托盘图标始终是同一张图，用户扫一眼任务栏不知道"现在有没有账号掉线"。
另外刷新是定时的，用户排障时想立刻刷一次却没有入口。

## 二、目标

托盘图标右下角出现一个状态小圆点：绿=全部在线、黄=有账号离线、红=有账号凭据损坏；
右键菜单与面板里都能"立即刷新"，不用等下一个刷新周期。

## 三、范围

**包含：**

* 图标徽标：在现有 128×128 托盘图标右下角合成一个圆形徽标（带深色描边，深浅背景下都可见）；
* 聚合规则（纯函数、可测）：
  * 无账号 → 不显示徽标（基础图标）；
  * 有「凭据损坏」→ 红；
  * 有「离线」→ 黄；
  * 全部在线 → 绿（品牌薄荷绿）；
  * 其余（未知/刷新中）→ 不显示徽标。
* 仅在聚合结果变化时 `set_icon`，避免每轮都重建图标；
* 托盘菜单新增「立即刷新」（id `refresh`）；面板总览卡片右侧新增「立即刷新」按钮；
* 手动刷新绕过定时与启动延迟，但仍受"同一时间只跑一轮"约束。

**不包含：**

* 图标按"账号数量"变形、按分组着色；
* 系统通知（托盘气泡提醒）；
* 面板内逐账号手动刷新；
* macOS 模板图标适配（仍走彩色图标，阶段 3 再说）。

## 四、设计要点

1. **徽标合成**：把内嵌 PNG 解码成 RGBA 后，在右下角画一个半径 `w/5` 的实心圆，
   先画 2px 深色描边、再填状态色，最后重新 `Icon::from_rgba`。
   纯函数 `compose_badge(rgba, width, height, rgb)`，便于单测（检查圆点中心像素）。
2. **聚合**：`aggregate_badge(cards) -> Option<[u8; 3]>`，只依赖运行态，不碰 UI。
3. **刷新入口统一**：托盘 `RefreshNow` 与面板按钮都调用 `start_refresh(force = true)`；
   定时路径调用 `start_refresh(force = false)`。`force` 只跳过"到点判断"，
   不跳过"已有刷新在跑"。
4. **线程安全**：图标只能在主线程设置；刷新结果回到 `logic()` 后统一更新，
   与 0004 的菜单重建同一时机。

## 六、验收标准

1. 操作：登录 1 个真实账号并等首轮刷新完成 → 预期：托盘图标右下角出现**绿色**圆点。
2. 操作：把该账号的地址改成一个不通的端口后重启（或断网）→ 预期：下一轮后圆点变**黄色**，
   账号不被删除。
3. 操作：手工把 `accounts.json` 里 `secrets` 改坏后重启 → 预期：圆点变**红色**，面板提示凭据损坏。
4. 操作：右键托盘 → 点「立即刷新」→ 预期：无需等待刷新间隔，约 1 秒内面板/菜单状态刷新，
   日志出现新的一轮"本轮状态刷新完成"。
5. 操作：面板总览卡片点「立即刷新」→ 预期：同上。
6. 操作：连续点「立即刷新」→ 预期：不会并发跑两轮（日志只出现一轮开始/结束）。
7. 操作：`cargo test` → 预期：聚合、徽标、菜单用例全部通过。

## 八、风险与回滚

| 风险 | 影响 | 应对 |
| --- | --- | --- |
| 频繁换图标导致任务栏闪烁 | 观感差 | 只在聚合结果变化时更新 |
| 徽标在浅色任务栏上不可见 | 看不清状态 | 先画深色描边再填色 |
| 手动刷新被连点 | 请求翻倍、触发限流 | `refresh_rx.is_some()` 时直接忽略 |

回滚：`git revert` 合并提交；图标更新与刷新入口都是独立代码路径，不影响数据层。
