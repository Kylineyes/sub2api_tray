## 一、背景

凭据解密失败时，用户只能删除本地账号后重新添加；这样会丢失账号展开状态和 API Key 摘要缓存。
同时，DPAPI 解密失败虽然已经带 Windows 错误码，但日志中不够醒目，排障时难以快速确认是跨用户/跨机器问题。

## 二、目标

在凭据损坏的账号上提供原地重新登录，并让 DPAPI/钥匙串错误码在日志中明确可见。

## 三、范围

**包含：**

* 凭据损坏账号展开后显示「重新登录」按钮；
* 重新登录弹窗预填并锁定实例地址与邮箱，只要求输入密码和 2FA；
* 成功后原地更新 `accounts.json` 中的加密凭据，不删除账号、不清 Key 缓存；
* 成功后立即触发一轮状态刷新；
* DPAPI/钥匙串解密失败日志明确标注，并保留底层错误码；
* 增加 DPAPI 错误码断言与重新登录弹窗测试。

**不包含：**

* 不支持跨 Windows 用户/跨机器迁移 DPAPI 密文；
* 不引入口令加密导出/导入；
* 不改变账号删除流程。

## 五、验收标准

1. 操作：凭据损坏账号展开 → 预期：显示「重新登录」按钮。
2. 操作：点击重新登录 → 预期：地址与邮箱已填入且不可编辑，只输入密码/2FA。
3. 操作：登录成功 → 预期：账号记录保留，Key 缓存保留，状态立即刷新。
4. 操作：查看日志 → 预期：DPAPI 解密失败包含底层 Windows 错误码。

## 七、风险与回滚

| 风险 | 影响 | 应对 |
| --- | --- | --- |
| 重新登录写错账号 | 覆盖其它凭据 | 弹窗锁定账号 id、地址与邮箱 |
| 加密失败 | 旧凭据保持不变 | 先加密成功后再落盘 |
| 跨机器密文仍失败 | 无法恢复 | 保留原账号，用户可重新登录 |

回滚方式：移除重新登录入口与 LoginDialog 模式，恢复为删除后重新添加。
